# Trend Watcher: от поиска трендов до календаря публикаций

**Объединил поиск сильных роликов и производство контента в одном приложении. У идеи сохраняются источник, метрики и сценарий; дальше она проходит через канбан к подготовке и публикации.**

[← Все кейсы](../README.md)

## Задача бизнеса

Найти удачный ролик — только начало. Нужно сохранить источник, понять содержание, подготовить свой сценарий и видеть, что уже взяли в работу. Для этого важно связать исследование рынка с производством контента.

Создавал приложение с поиском по ключевым словам, мониторингом каналов, анализом видео и контентной CRM: карточками, этапами работы и календарём публикаций.

## Что получает команда

- **Отбор опирается на данные.** Рядом с роликами видны просмотры, вовлечение и другие показатели.
- **Материал сохраняется целиком.** Источник, транскрипт, новый сценарий и комментарии связаны в карточке.
- **Понятно, что делать дальше.** Канбан и календарь показывают этап производства и дату публикации.

## Мой вклад

Создал серверную часть и браузерный интерфейс, подключил источники данных и AI-обработку. Реализовал базу материалов, контентную CRM, права доступа, фоновые задания и расписания сбора. Добавил режим PostgreSQL, перенос данных из Airtable и подготовку серверного развёртывания.

## 1. Поиск и аналитика трендов

В YouTube можно искать каналы и ролики по ключевым словам, собирать видео выбранных каналов и обновлять статистику. Для Instagram предусмотрены отдельные сценарии работы с профилями и Reels.

В подборке доступны просмотры, просмотры в день, вовлечение и отношение просмотров к размеру аудитории. Фильтры, сортировки и сохранённые представления помогают выбирать материалы под конкретную нишу. Повторно найденные каналы объединяются по идентификаторам.

Это data pipeline — последовательный поток данных от внешнего API до общей базы и рабочего экрана. Для YouTube учитываются квоты запросов: ограничения сервиса видны на уровне сбора.

## 2. Контентная CRM

Внутри приложения материал становится рабочей карточкой. В ней связаны исходный ролик, транскрипт, новый сценарий, описание, комментарии и дата публикации.

| Инструмент | Как используется |
| --- | --- |
| База каналов и видео | Сохраняет источники, метрики и результаты обработки |
| Статусы отбора | «В работе», «Не берём» и «Взять позже» помогают разобрать найденное |
| Канбан производства | Сценарий → съёмка → монтаж → проверка → публикация |
| Календарь | Показывает запланированные публикации по датам |
| Представления и фильтры | Открывают нужную подборку для текущего этапа работы |

Контентная CRM здесь означает ведение материалов и этапов их производства. Карточка остаётся связана с исходной идеей при переходе между этапами.

## 3. AI-обработка материалов

Для выбранного видео система получает транскрипт через Apify; при отсутствии текста пробует резервный источник субтитров RapidAPI. OpenAI готовит новую версию текста, начальную фразу для привлечения внимания, описание и хэштеги. Результаты сохраняются в карточке вместе со статусом обработки.

Инструкции для модели задаются в настройках — это prompt engineering: управление задачей, контекстом и форматом ответа. Human-in-the-loop реализован через ручной отбор материалов и этап проверки в производственной доске: человек выбирает идею и проверяет подготовленный контент.

## Архитектура и эксплуатация

| Слой | Технологии и решения |
| --- | --- |
| Интерфейс | HTML, CSS, JavaScript; таблицы, канбан и календарь |
| Сервер | Node.js, HTTP API, модули сбора и обработки |
| Данные | Airtable или PostgreSQL; перенос записей между режимами |
| Интеграции | YouTube Data API, Apify, OpenAI, RapidAPI |
| Фоновые процессы | Сохраняемая очередь заданий, расписания и история выполнения |
| Доступ | Учётные записи, сессии, администратор и разрешения по нишам |
| Развёртывание | Docker Compose, резервное копирование и восстановление PostgreSQL |

Ролевой доступ (RBAC) проверяется на сервере: обычный пользователь работает только с назначенными нишами, администратор управляет доступами и сбором. Долгие операции выполняются в фоне, а интерфейс показывает их состояние.

## Проверка и результат

Приложение работает локально с PostgreSQL. Подготовлены контейнерный комплект и процедура переноса на Linux; восстановление базы и сохранность данных проверялись на изолированной копии. В проекте предусмотрены модульные и браузерные проверки.

В одной системе объединены поиск трендов, база источников, AI-подготовка текстов и ведение контента до публикации. Публичное серверное размещение пока не подтверждено. Доступность внешних видео и AI-обработки зависит от ключей, квот и ограничений платформ.

**Статус:** рабочее локальное приложение, развитие продолжается.
